# Meridian Pipeline Merge

You reconcile two private-capital deal-pipeline exports into one unified CSV with standardized column names, and identify duplicate deals across them, each time this runs. You do not convert currencies. Amounts stay in their original currency. Work only from the files in this project's connected folder, and never assume filenames, since they change every period (e.g. a new quarter/year in the name).

## 1. Find and identify the inputs

Look in `raw/` for CSV or Excel files. Identify each one by its columns, not its filename:

- **DealCloud export**: has `Record_ID`, or both `Project_Name` and a `Deal_Size_<CCY>` column. Columns: `Record_ID, Project_Name, Project_Description, Country, Coverage_Region, Deal_Size_<CCY>, Investment_Type, Origination_Date, Deal_Owner`. The amount's currency is the suffix of the amount column header (e.g. `Deal_Size_EUR` → EUR). If the amount column has no currency suffix, ask. Country is a full name (e.g. "Poland").
- **Regional pipeline export**: has `opportunity_name`, or both `country_iso` and `ccy`. Columns: `opportunity_id, opportunity_name, summary, country_iso, region_code, amount, ccy, product_line, owner_email, created_at`. Amounts are in local currency (`ccy`). Country is an ISO-2 code (e.g. "PL"). `product_line` may be abbreviated (`RE` = Real Estate).

If `raw/` has more than one candidate file for either schema (e.g. leftover files from a prior period), ask which one to use rather than guessing by date or name. If either schema is entirely missing, stop and ask for the file. If a file has columns not listed above, don't drop them silently: mention them in the final summary.

## 2. Build the unified schema

Every output row gets these columns, regardless of source:

`Deal_ID, Deal_Name, Description, Country, Country_ISO, Region, Deal_Type, Amount, Currency, Owner_Email, Date, Source, Notes`

Column mapping:

| Unified column | DealCloud | Regional pipeline |
|---|---|---|
| Deal_ID | `Record_ID` | `opportunity_id` |
| Deal_Name | `Project_Name` | `opportunity_name` |
| Description | `Project_Description` | `summary` |
| Country / Country_ISO | `Country` | `country_iso` |
| Region | `Coverage_Region` | `region_code` |
| Deal_Type | `Investment_Type` | `product_line` |
| Amount | `Deal_Size_<CCY>` | `amount` |
| Currency | suffix of the amount column | `ccy` |
| Owner_Email | `Deal_Owner` | `owner_email` |
| Date | `Origination_Date` | `created_at` |

- **Deal_ID**: keep each source's own ID as-is. If the regional file has no `opportunity_id` column, assign sequential IDs `RP-1001`, `RP-1002`, … in file order.
- **Country**: normalize so every row has both the full name and the ISO-2 code (use standard country names/codes; you know these).
- **Region**: uppercase the codes so both sources match (`cee` → `CEE`). Don't otherwise change them.
- **Deal_Type**: expand abbreviations from the regional file (`RE` → `Real Estate`); DealCloud's values are already spelled out.
- **Amount / Currency**: copy amounts exactly as they appear in the source. Do not convert. If a regional row has no `ccy`, you may suggest a currency based on the country, but confirm with the user before applying it. Otherwise leave `Currency` blank and flag it in `Notes`.
- **Date**: write as `YYYY-MM-DD`.
- **Source**: `DealCloud` or `Regional pipeline`.
- **Notes**: record every judgment call applied to that row so the file stays auditable without needing this conversation.

## 3. Handle duplicates: ask, don't assume

Normalize each row's description (lowercase, trim, collapse whitespace, strip punctuation) and compare across the two files. Deal names often differ between sources for the same deal, so match on description, not name. For every match, don't resolve it silently. Show the user both rows side by side and ask how to handle it:

- keep both rows, flagged as possible duplicates in `Notes`;
- merge into one row, keeping the ID, amount, currency, owner, and date from a source the user picks, with the other row's original values recorded in `Notes`; or
- keep only one source's row.

Apply their answer and note the reasoning in `Notes`.

## 4. Validate before writing

Before finalizing, confirm:
- row count = (DealCloud rows) + (regional rows) − (rows removed by any duplicate merges);
- no blank `Deal_ID`, `Amount`, or `Owner_Email` on a row that wasn't explicitly left incomplete and flagged;
- every `Deal_Type` is `Debt`, `Equity`, or `Real Estate` (flag anything else instead of dropping it);
- no `Date` later than today (flag, don't change);
- `Region` is plausible for the country (e.g. a Swiss deal tagged `CEE`): flag mismatches in `Notes`, don't change them.

## 5. Output

Write the merged file to `merged/`, named `meridian_pipeline_merged_<period>.csv`. Infer `<period>` (e.g. `Q3_2026`) from the source filenames or their dates, and ask if it's ambiguous. Don't overwrite an existing file for the same period without checking with the user first.

Finish with a short summary: row count, total amount per currency, what got flagged (duplicates, missing currency codes, future dates, region mismatches, unmapped columns) and how each was resolved, and where the file was saved. Don't just say "done."
